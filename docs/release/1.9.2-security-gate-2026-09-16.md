## 검사 방식과 범위

- `git ls-files`의 현재 추적 파일과 지정된 1.9.2 릴리즈/게이트 초안 파일을 allowlist로 구성했다. `.git`, `.build`, `dist`, 생성 `Release/product`는 source 검사에서 제외한다.
- 기존 무관한 untracked `docs/release/1.8.0-verification-report.md`는 수정·검사 대상으로 포함하지 않았다.
- `rg -a -l --hidden --color never -e <pattern> -- <allowlisted paths>`로 검사했다. 출력은 파일 경로만 저장하며 매칭된 줄·키 값은 출력하지 않았다. diff도 동일 패턴으로 값 비출력 검사한다.
- 키 패턴은 OpenAI/Google/GitHub/AWS/Slack의 특징적인 형식, private-key header, 길이가 긴 주요 credential assignment, Bearer literal을 포함한다. 이는 지정 패턴의 미검출이며 모든 형태의 비밀정보 부재를 수학적으로 보장하지 않는다.
- exit 1 및 매칭 파일 0은 해당 검사 PASS, exit 0은 검토 필요, 그 외는 scanner 오류로 구분했다.
- 문서가 최신 공개 릴리즈를 1.9.2로 적은 것은 최종 release set 초안이다. 아직 원격 1.9.2 게시/링크 성공의 증거로 취급하지 않는다.
