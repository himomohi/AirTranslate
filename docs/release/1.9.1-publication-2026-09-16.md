## 반복 실행과 실패 흡수

45회차는 기존1.9.0 게시를 마친44회차 다음의 별도 릴리즈 실행이다. 같은 회차 안에서도 발견된 실패를 수정한 뒤 필요한 게이트를 다시 실행했다.

| 발견 | 흡수 | 결과 |
| --- | --- | --- |
| 새 테스트의 custom font·모드 값 간섭 | UUID UserDefaults와 명시적 모드, cleanup | 집중·전체 PASS |
| 기존 LongSession checkpoint 간헐 실패2회 | 공식 문서4개 후보 검토 후 helper의 설정·파일 저장소 격리 | 제품 주기·timeout·병렬 실행 보존, 집중7개·전체326개 PASS |
| ColorPicker 창이 도구에 안 보임 | 메인 창을 닫고 별도 Colors 창 확인, UI 실패와 창 선택 한계를 구분 | native panel 열림 확인; 정밀 HEX 입력 경로의 적용·저장도 검증 |
| 드래그·극단 크기·preset override 경계 | event 위치 기반 이동/resize, 동적 최소높이·effective line count, preset 명시 복귀 | 실제 드래그·회귀 PASS |
| resize handle AX 누락·투명 배경 낮은 대비 | accessibility element 노출, 검은 외곽선 | 실제 AX Increment 및 0% 배경 캡처 PASS |
| 이전 DMG 동시 마운트 충돌 | verifier→security 순차 마운트 소유 | 최종 자산 결과에 기록 |

[Swift Testing 병렬화](https://developer.apple.com/documentation/testing/parallelization)와 [UserDefaults suite](https://developer.apple.com/documentation/foundation/userdefaults/init(suitename:)) 문서를 바탕으로 테스트 저장소 격리를 선택했다. 제품 저장 주기를 늘리거나 테스트 timeout을 느슨하게 만들지 않았다.

역할은 macOS implementer·release operator·security auditor·test verifier·report writer로 분리했다. 커스텀 역할은 프로젝트 설정을 따랐고, 지정 테스트 모델 미지원 이후 검증·보고는 메인 모델/추론을 상속한 작업자가 맡았다. 실제 backend model ID가 도구에 별도로 노출되지 않아 역할 설정을 실제 모델 확인으로 주장하지 않는다. 구현자 재호출이 thread limit으로 거절된 후 HEX·실제 UI 보완은 코디네이터가 직접 통합했다.
