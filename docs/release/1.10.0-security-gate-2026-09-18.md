# AirTranslate 1.10.0 Security Gate

Date: 2026-09-18 KST
Version/build: 1.10.0 / 1100
Scope: source, public wording, release ZIP/DMG/checksum artifacts, extracted or mounted app bundles, final verification reports, and harness maturity notes.

## Status

| Gate | Status | Evidence |
| --- | --- | --- |
| Source and docs | PASS | Secret-pattern scan returned exit 1 with no matches; sensitive-file scan returned no paths; release wording now says Grok STT is included from 1.10.0 and keeps live xAI verification limits explicit. |
| Keychain and Grok network path | PASS | `GrokAPIKeyStore` uses separate `AirTranslate.Grok` / `XAI_API_KEY` generic-password storage; presence checks do not return secret data and skip Keychain authentication UI. `GrokRealtimeTranscriber` uses fixed `wss://api.x.ai/v1/stt`, sends the key only in the `Authorization` header, uses ephemeral URLSession storage, and rejects redirects. |
| Release artifacts | PASS | Two ZIP apps and two DMG apps are 1.10.0/1100, contain LICENSE/NOTICE, pass strict codesign verification, are ad-hoc signed with Hardened Runtime, have `com.apple.security.device.audio-input=true`, and do not include `get-task-allow`. |
| Secret/sensitive-file artifacts | PASS | Extracted ZIP trees and mounted DMG trees had `secret_hit_count=0` and `sensitive_file_count=0`. Keyword hits were limited to expected app binary `Authorization` runtime strings. |
| DMG/checksum/mount cleanup | PASS | Both DMGs passed `hdiutil verify`; both `.sha256` files matched their target DMGs; both read-only mounts detached and no AirTranslate mount remained. |

Security does not block tag, push, or upload. Remote post-upload verification is still required after GitHub Release upload: re-download the six assets, compare SHA-256, repeat the artifact secret/sensitive-file checks, and verify release links before calling the remote release gate complete.

## Findings

| Severity | Finding | Status |
| --- | --- | --- |
| Low | Real xAI account authentication, quota behavior, speech-recognition quality, and latency were not tested with a live API key or paid API call. Public docs and release notes state this boundary. | Accepted residual limitation |
| Informational | Artifact keyword scan found `Authorization` in each app binary. This is expected because the app constructs provider authorization headers at runtime. No bearer token, `xai-...` key, `XAI_API_KEY=...` assignment, private key, certificate, provisioning profile, or `.env` file was found. | No block |

## Public Wording Risks

PASS. README files, release notes, setup docs, privacy notice, changelog, and version history now describe Grok STT as included from 1.10.0. They also preserve these required public boundaries:

- user supplies their own xAI key;
- audio is sent directly to xAI only when Grok capture starts;
- saved/configured key is not provider authorization proof;
- live xAI authentication, quota behavior, recognition accuracy, and latency are unverified;
- AirTranslate is independent and not affiliated with SpaceXAI (xAI);
- DMG/ZIP artifacts are ad-hoc signed and not Apple-notarized.

Historical file `docs/grok-stt-verification-2026-09-18.md` still says the feature was not published at the time of that implementation check. That is acceptable because it is a dated implementation record, not current public release copy.

## Residual Requirements

- After GitHub upload, re-download every published asset and compare SHA-256 with the manifest above.
- Repeat artifact secret/sensitive-file checks on the downloaded assets.
- Verify the GitHub Release page and download URLs resolve to the expected version.
- Live xAI API authentication, paid transcription behavior, accuracy, latency, and quota behavior remain unverified until tested with a real user key and real audio.
