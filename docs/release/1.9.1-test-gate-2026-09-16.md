## 실패 처리와 검증 경계

- 첫 전체 검사에서 새 자막 테스트 3개의 기대값 4개가 실패했다. 테스트 간 `UserDefaults.standard` 공유로 72pt 사용자 지정 크기와 표시 모드가 다른 테스트에 영향을 주는 정황을 확인했다. 해당 세션 테스트 4개를 UUID별 suite와 종료 후 정리 방식으로 격리하고, 폰트 기본값을 명시했다. 구현 담당자의 집중 25개 재검사 및 검증 담당자의 전체 검사에서 자막 실패가 해소됐다. 제품 소스를 바꾸거나 테스트를 직렬화하지 않았다.
- 기존 `runningSessionCheckpointsTranscriptWithoutStopping`의 1.5초 저장 대기 조건이 전체 실행에서 두 번 실패했다. 첫 실패 후 단독 1개(0.199초)와 전체 325개는 통과했으나, HEX 변경 후 전체 실행에서 재발하여 재시도를 중단했다. 공식 문서에서 ① UserDefaults 격리, ② 비동기 완료 조건을 먼저 기다리는 방식, ③ suite 직렬화의 한계, ④ 결정적 clock/완료 신호 주입을 비교했다. 기존 helper가 설정을 공유하는 문제를 제거하는 최소 수정으로 각 세션에 UUID UserDefaults를 주입하고 임시 디렉터리와 함께 정리했다. 집중 7개와 최종 기본 병렬 전체 326개가 통과했다. 제품 checkpoint 구현, 1.5초 timeout, 병렬 실행은 변경하지 않았다. 시간 지연의 유일한 원인까지 계측으로 확정했다고 주장하지 않으며, 반복 실패에서 확인한 설정 공유 위험을 테스트 격리로 제거했다.
- 근거 문서: [Apple의 병렬 테스트 설명](https://developer.apple.com/documentation/testing/parallelization), [UserDefaults suiteName](https://developer.apple.com/documentation/foundation/userdefaults/init(suitename:)), [Swift Testing 마이그레이션의 공유 상태·비동기 안내](https://docs.swift.org/latest/documentation/testing/migratingfromxctest/), [WWDC의 병렬 테스트 및 비동기 조건 안내](https://developer.apple.com/videos/play/wwdc2024/10195/). `.serialized`는 해당 suite 내부만 직렬화하므로 다른 suite와의 설정 공유를 해결하는 근거로 사용하지 않았다.
- 공개용 앱의 ad-hoc 서명 및 notarization 부재는 기존 배포 방식이다. Developer ID 서명, 새 사용자 기기의 Gatekeeper 통과, macOS 26에서의 실제 실행을 검증했다고 주장하지 않는다.
- 실제 클라우드 계정·사용자 키 입력·오디오 캡처를 수행하지 않았다. 보안 담당자의 최종 판정 및 원격 업로드 후 다운로드 검증은 별도 결과와 결합한다.
- 제품 소스·커밋·push·tag·GitHub 게시를 변경하지 않았다. Coordinator가 명시적으로 위임한 `LongSessionCaptionPresentationTests.swift`의 설정 격리, 본 보고서와 생성 자산을 담당한다.
