## CI 타이밍 실패와 실행 격리 보완

- 최초 원격 실행 [35349711301](https://github.com/himomohi/AirTranslate/actions/runs/35349711301)은 전체366개 중 기존 `runningSessionCheckpointsTranscriptWithoutStopping`의1.5초조건만 실패했다. Grok 회귀와 반복 회귀는 통과했다. 이 실패를 전체PASS로 표현하지 않는다.
- 같은 테스트의 단독·직렬 성공과 동시 MainActor 작업 중 실패 이력을 근거로 테스트 간 스케줄링 경합을 유력 원인으로 판단했다. 실제 타이머40ms와 MainActor 작업을 사용하는 구현이며, 제품 저장 실패로 확정하지 않는다.
- 공식 문서를 확인하고 네 후보를 비교했다. suite `.serialized`는 무관한 다른 suite와의 경합을 막지 않는다. 가상 Clock 주입은 제품 구현 변경이 필요하다. 먼저 특정 테스트만 별도 프로세스에 분리했으나, 남은365개 병렬 검사에서 `retranslationOfGrowingSourceIsHeldUntilTranslationDwellElapses`도 시간 경합으로 실패했다. 단독 checkpoint는0.708초에 통과했다.
- 서로 다른 실제 시간 기반 테스트가 공유 MainActor에서 간섭하는 범위임을 확인해 최종 CI는 `swift test --no-parallel`로 전체366개를 순차 실행한다. 테스트 수·본문·assertion·제품 timeout은 모두 유지한다. 개별 테스트 내부에서 생성하는 동시성 작업 검증도 유지한다. 특정 테스트를 제외하거나 성공할 때까지 반복하지 않는다.
- [Swift Testing 병렬화](https://developer.apple.com/documentation/testing/parallelization), [비동기 테스트](https://developer.apple.com/documentation/testing/testing-asynchronous-code), [Clock 주입 논의](https://forums.swift.org/t/pitch-clock-sleep-for/60376)를 참고했고 로컬 `swift test --help`로 실행 옵션을 확인했다.
- 게시된 v1.10.0 태그와6자산은 보존하고 CI·보고서 수정만 master에 후속 직접 반영한다. 사용자가 PR 없이 직접 업로드할 것을 재확인했다.

- 최종 실행 구성으로 로컬366개/39 suites가23.556초에 다시PASS했다. 독립 보안 검토도 전체커버리지·contents:read·checkout자격증명비지속·빌드/패키징/스캔게이트보존을 확인해PASS했다.
